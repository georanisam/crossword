# Apps Script 백엔드 (Code.gs)

이 앱의 데이터는 전부 Google Sheets에 있고, 그 앞단이 이 `Code.gs`(Apps Script 웹앱)다.
**느리다 / 안 된다 / 오류난다 는 거의 전부 여기서 생긴다.** 프런트(`index.html`, `student.html`)는
이 웹앱을 부르기만 한다.

- 웹앱 URL은 `index.html` / `student.html` 의 `GAS_URL` 상수에 하드코딩돼 있다.
- 이 폴더의 `Code.gs`는 **소스 사본**이다. Vercel은 이 파일을 쓰지 않는다.
  고쳐도 Apps Script 편집기에 붙여넣고 재배포하기 전까지는 아무 일도 일어나지 않는다.

---

## 배포하는 법 (⚠️ 순서 중요)

1. https://script.google.com 에서 이 프로젝트를 연다
   (연동 시트 → 확장 프로그램 → Apps Script 로 들어가도 된다).
2. **먼저 지금 편집기에 있는 코드를 통째로 복사해 딴 데 백업**해 둔다.
3. Gemini API 키를 안전한 곳으로 옮긴다 (한 번만 하면 된다):
   왼쪽 **⚙ 프로젝트 설정 → 스크립트 속성 → 속성 추가**
   - 속성: `GEMINI_API_KEY`
   - 값: 백업해 둔 코드의 `GEMINI_API_KEY = '...'` 안에 있던 실제 키
   이렇게 해두면 앞으로 코드를 갈아끼워도 키가 지워지지 않는다.
4. 편집기의 `Code.gs` 내용을 전부 지우고 이 폴더의 `Code.gs`를 붙여넣는다. 저장(💾).
5. **배포 → 배포 관리 → (기존 배포의) ✏️ 연필 → 버전: `새 버전` → 배포**

> ### 🚨 5번에서 절대 하면 안 되는 것
> **[새 배포]를 누르면 안 된다.** 새 배포는 **새 URL**을 만들고,
> 그러면 `GAS_URL`이 안 맞아서 앱 전체가 멈추고 이미 나눠준 학생 링크·QR도 전부 죽는다.
> 반드시 **기존 배포를 편집해서 "새 버전"으로 올리기**.

6. 배포 권한은 그대로 두면 된다: **실행 사용자 = 나**, **액세스 권한 = 모든 사용자**.

### 선생님 비밀번호 (`TEACHER_PW`)

`Code.gs`의 `handle()`이 학생용 동작(`ping`, `getQuizForPlay`, `submitAnswer`)을 뺀
나머지를 전부 비밀번호로 막는다. 비밀번호는 **스크립트 속성 `TEACHER_PW`** 에 둔다
(코드에 적으면 GitHub에 올라간다).

- `TEACHER_PW` 속성이 **없으면 잠금이 꺼진다.** 설정 전에 선생님이 갇히지 않게 한 것이다.
  속성을 만드는 순간부터 켜진다. → **잠그려면 반드시 속성을 만들어야 한다.**
- `index.html`의 `TEACHER_PW_HASH`와 값이 **같아야** 한다. 다르면 선생님 화면에서
  "선생님 비밀번호가 필요합니다"가 뜨고 다시 잠긴다.
- 자세한 배경은 저장소 루트의 `APPS_SCRIPT_보안패치.md`.

> ⚠️ **이 코드를 통째로 갈아끼울 때마다 비밀번호 검사도 같이 날아갈 수 있다.**
> 실제로 2026-09-10에 성능 패치를 붙여넣으면서 한 번 날아갔다.
> 붙여넣은 뒤에는 아래 "배포 후 확인"의 잠금 테스트를 꼭 해볼 것.

## 배포 후 확인

브라우저에서 GAS_URL 뒤에 `?action=ping` 을 붙여 열어본다.
`{"ok":true,"msg":"pong"}` 이 나오면 정상.

**잠금 테스트** — 같은 주소 뒤에 `?action=getSubmissions` 를 붙여 연다.
`{"ok":false,"error":"선생님 비밀번호가 필요합니다."}` 가 나와야 한다.
학생 기록이 그대로 쏟아지면 `TEACHER_PW` 속성이 없는 것이다.

그다음 선생님 화면에서 [저장된 퀴즈] → [제출 현황] 순으로 눌러보고,
학생 링크를 하나 열어 **학번/이름 화면이 바로 뜨는지** 확인한다.

## 이 백엔드가 지키는 원칙 (건드릴 때 주의)

### 캐시가 핵심이다
한 반 30명이 같은 링크를 동시에 열면 예전엔 똑같은 퀴즈를 시트에서 30번 읽었다.
지금은 `CacheService`에 담아 한 번만 읽는다. 캐시 키는 네 종류:

| 키 | 내용 | 언제 버려지나 |
|---|---|---|
| `row_{quizId}` | 퀴즈 원본 행 | 퀴즈 저장/삭제 (`bustQuiz_`) |
| `play_{quizId}` | 학생에게 주는 퀴즈(정답 없음) | 퀴즈 저장/삭제 |
| `grade_{quizId}` | 채점용 정답 셀맵 | 퀴즈 저장/삭제 |
| `subcount` | 퀴즈별 제출 수 | 새 제출이 들어올 때 |
| `sub_{attemptId}` | 방금 처리한 제출의 결과 | 15분 뒤 자동 |
| `init_{시트이름}` | 헤더 확인을 이미 했다는 표시 | 6시간 뒤 자동 |

**퀴즈 내용을 바꾸는 코드를 새로 쓰면 반드시 `bustQuiz_(quizId)`를 같이 불러야 한다.**
안 그러면 선생님이 퀴즈를 고쳐도 학생은 최대 6시간 동안 옛날 퀴즈를 받는다.

### 시트는 필요한 열만 읽는다
`getValues()`로 넓게 읽으면 안 쓰는 열까지 다 딸려온다. 특히:
- 퀴즈목록 7열(`quizData`)은 퀴즈 하나당 수 KB짜리 JSON → 목록 조회에서 읽지 않는다.
- 제출기록 12열(`wordResults`)은 제출 한 건마다 붙는 JSON → 제출 목록에서 읽지 않는다.

### 제출은 두 번 기록되면 안 된다
학생 화면이 응답을 못 받으면 자동으로 다시 보낸다. 그래서 제출마다 `attemptId`가 붙고,
서버는 이미 처리한 `attemptId`면 새로 쓰지 않고 이전 채점 결과를 그대로 돌려준다.
(학생이 [다시 제출]을 눌러 새로 채점받는 건 `attemptId`가 달라지므로 정상 기록된다.)

### 응답은 항상 JSON이어야 한다
`handle()`이 모든 예외를 잡아 `{ok:false, error:...}` 로 돌려준다.
여기서 예외가 새어나가면 Apps Script가 HTML 오류 페이지를 보내고,
프런트는 그걸 파싱하지 못해 "서버가 잠시 응답하지 못했어요" 로 처리한다.

### CORS
프런트가 `fetch`에 `Content-Type`을 지정하지 않아 `text/plain`으로 나간다.
그래야 브라우저가 preflight(OPTIONS)를 안 보낸다 — **Apps Script는 OPTIONS에 응답하지 못한다.**
`Content-Type: application/json`이나 `Authorization` 헤더를 붙이는 순간 전부 깨진다. 바꾸지 말 것.
